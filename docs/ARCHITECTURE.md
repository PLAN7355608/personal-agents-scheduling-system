# 架构说明 / Architecture Notes

本文说明 PASS 的分层、数据流与关键设计取舍。交互式节点图见 [`assets/arch-v0.4.html`](../assets/arch-v0.4.html)。

## 1. 三条原则

1. **账本即真相**：任务的每一次状态变化、工具调用、审批、产物都写进 append-only 事件表；内存与投影都可以从事件重建。
2. **传话与干活分离**：Relay 只负责听懂、建单、汇报；执行永远交给独立 Worker 会话，避免「对话模型直接动手」带来的越权与不可控。
3. **默认不打扰，越界必审批**：普通任务静默完成；工具白名单之外、系统边界（系统目录、提权命令、hosts）一律要求主人批准。

## 2. 分层

```
┌──────────────────────────────────────────────────────────┐
│ 入口层：GUI 对话（Relay preset） / HTTP / 外部通道         │
└───────────────┬──────────────────────────────────────────┘
                │ secretary_create_task（默认异步，建完即返回）
┌───────────────▼──────────────────────────────────────────┐
│ 内核（Host 插件，常驻）                                    │
│  ├─ WorkItem 状态机：intake → triaged → queued → running   │
│  │                    → done / failed / blocked / cancelled│
│  ├─ 事件账本（SQLite，append-only，schema v16）            │
│  ├─ 线（Lane）路由：一来源一线；线内串行、线间并行          │
│  ├─ 派单：每线一个 Worker 会话（空闲卸载、复用不换人）      │
│  ├─ 工具治理：白名单 → 申请 → 规则/judge → 主人审批         │
│  ├─ 删除护栏 / 系统边界护栏 / 派单去重 / 看门狗             │
│  └─ HTTP：面板、状态、任务、审计（只读 + 同源审批写）       │
└───────────────┬──────────────────────────────────────────┘
                │ 任务提示词（含事实/记忆/文件清单）
┌───────────────▼──────────────────────────────────────────┐
│ Worker 会话（独立 preset：工具面 + 权限档 + 审批策略）      │
│  ├─ 文件 / 终端 / 搜索 / Office / 图像 等工具              │
│  ├─ 白名单外工具 → secretary_request_tool → 审批           │
│  └─ 结束 → secretary_work_finish → 账本 → 面板/回灌        │
└──────────────────────────────────────────────────────────┘
```

## 3. 数据流（一次任务）

1. 用户在 GUI 说一句话 → Relay 调 `secretary_create_task`，传需求原文、工作区、可选模型/工具档；
2. 内核落库（`item.created`），按「来源会话 + 工作区 + 焦点」路由到一条线（`item.state: triaged → queued`）；
3. 派单器确保该线有 Worker 会话（没有则建，空闲则 resume 并重新挂 preset），投递任务提示词（`running`）；
4. Worker 执行工具；超出白名单或触碰系统边界时走申请/审批；工具调用事件写入账本；
5. Worker 调 `secretary_work_finish`/`_work_fail` → 状态落 `done`/`failed`，产物登记；
6. 面板轮询 `/secretary/v1/panel` 展示；若来源会话需要回灌（`guiNotify` 或任务 `notify=true`），内核把结果投回该会话。

## 4. 关键模块

| 文件 | 职责 |
|---|---|
| `index.js` | 工具注册、HTTP 路由、定时器（简报/归档/看门狗）、Relay/Worker 守卫、审批编排 |
| `src/db.js` | SQLite 打开、WAL、迁移（v1–v16） |
| `src/workitems.js` | 状态机、投影重建、任务读写 |
| `src/events.js` | 事件追加与查询（账本唯一写入口） |
| `src/dispatch.js` | 派单、工人会话创建/恢复、模型选择、提示词拼装 |
| `src/guard.js` | 工具白名单、Relay/Worker 越权拦截 |
| `src/protected.js` | 系统保护路径 / 提权命令识别 |
| `src/deletion-guard.js` | 删除命令范围与规模护栏 |
| `src/dedupe.js` | 派单去重（LCS 相似度） |
| `src/tool-requests.js` | 工具申请、授权范围（once/lane/global）、过期 |
| `src/judge.js` | 规则之外的裁判（judge）调用 |
| `src/recovery.js` | 启动恢复：重建投影、修补跑飞的状态 |
| `src/outbox.js` | 外部通道投递与重试 |
| `src/briefing.js` / `src/prune.js` / `src/archive.js` | 简报、清理、归档（默认只提议） |
| `client.js` | 右下角胶囊面板（状态、待办、工具申请审批按钮） |

## 5. 设计取舍

- **为什么事件账本而不是直接改表**：可回放、可审计、崩溃恢复有依据；代价是投影需要重建逻辑（已单测覆盖）。
- **为什么一线一会话**：模型有上下文，复用同一工人能保持对项目的理解；线隔离避免互相污染；代价是线内必须串行。
- **为什么默认异步**：工人跑一单可能几分钟，同步等待会锁死对话；`secretary_wait` 保留给「我就要等结果」的场景。
- **为什么系统边界强制审批**：工人能执行命令，一旦放开 hosts/系统目录/提权，等于把机器交给模型；宁可多一步审批。
- **审批默认 ask**：无人值守时审批请求失败即拒绝（fail-closed），不会静默放行。

## 6. 已知边界

- 单机单用户；多机同步、多用户隔离未实现；
- 取消只能让工人在下一次工具调用时停手，不能中断正在执行的命令或模型生成（依赖 DSH 提供 abort 接口）；
- 看门狗按「任务最近事件」判活跃，超长单条命令仍可能被判定无进展；
- 自动选模型接口预留未启用；打印/扫描等硬件工具默认关闭。
